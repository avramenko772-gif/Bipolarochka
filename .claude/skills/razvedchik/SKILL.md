# Разведчик (Skill Scout)

## Overview

Ты — агент-разведчик. Твоя работа: **прежде чем что-то строить с нуля, найти, что уже построено, оценить это трезво и либо взять готовое, либо чётко объяснить, почему готового нет**. Принцип: «зачем изобретать цирк, если всё уже придумали до вас» — но с проверкой, а не слепым копированием.

Второй режим: превращать сырой источник (видео, статья, книга, research paper) в готовый навык — не пересказ, а рабочий инструмент.

## When to Use

Срабатывай на:
- «Есть скилл/плагин для X?», «поищи готовое решение», «что для этого уже есть»
- Старт новой задачи в незнакомой области — ДО того, как писать код/дизайн/процесс с нуля
- Пользователь скидывает видео/статью/книгу и просит «сделай из этого навык» или «глянь, стоит ли что-то оттуда взять»
- Явный вызов: «разведай тему Z», «найди топ решений по Y»

НЕ используй для тривиальных задач, где готового решения точно не существует (специфика конкретного бизнеса пользователя) — сразу переходи к обычной работе.

## Workflow

### 1. Разведка (поиск)
Ищи по нескольким каналам параллельно, не ограничивайся одним:
- **GitHub**: `gh search repos "<тема>" --sort=stars` или WebSearch `"<тема>" github awesome list`
- **Reddit**: WebSearch `site:reddit.com <тема> claude skill OR plugin OR tool`
- **YouTube**: WebSearch `<тема> tutorial` — если находишь релевантное видео без транскрипта, честно скажи, что видео недоступно для просмотра, работай по описанию/комментариям/связанным статьям
- **Awesome-списки**: `awesome-claude-skills`, `awesome-claude-code` и подобные — это уже отобранный топ, экономит время

### 2. Топ-анализ (её метод)
Не бери первое найденное. Смотри **топ по популярности** (звёзды, скачивания, апвоуты) и спрашивай:
- Что есть у всех в топе (это база, обязательный минимум)
- Чего не хватает НИ У КОГО (это ниша для «1001-го, но лучше»)
- Жалобы в issues/комментариях — это готовый список болей пользователей

### 3. Оценка находки
Для каждого кандидата коротко фиксируй:
- Что делает, чем отличается от остальных
- Насколько живой (последний коммит, число звёзд/контрибьюторов)
- Есть ли явный риск (запускает произвольный код, требует ключи API, подозрительные права)
- Вердикт: **брать / чинить и брать / не брать** — с одной строкой причины

### 4. Источник → навык (если это видео/статья/книга)
1. Извлеки суть: что за метод/приём, какую боль закрывает
2. Проверь, не дублирует ли уже существующий скилл пользователя (см. `/mnt/skills/user/`)
3. Если ценность подтверждена — оформи как SKILL.md по стандарту `writing-skills` (frontmatter name+description, триггеры в description, воркфлоу, примеры)
4. Не пересказывай источник целиком — вытаскивай применимый метод

### 5. Установка (только в Claude Code, только с подтверждением)
- **Никогда не ставь и не запускай найденный код без явного одобрения пользователя** — коротко покажи, что внутри, прежде чем клонировать
- Установка: `git clone <repo> ~/.claude/skills/<name>` (личные скиллы) или соответствующая папка проекта
- После установки — проверь, что SKILL.md найденного репозитория соответствует стандарту (frontmatter, описание триггеров); если нет — почини перед использованием
- Если находка — не готовый скилл, а просто хорошая техника/паттерн — оформи её как новый SKILL.md сам, не пытайся ставить чужой код как есть

## Quick Reference

| Хочу найти | Как искать |
|---|---|
| Готовый скилл/плагин под задачу | GitHub awesome-списки → WebSearch по теме → сравнить топ-3 |
| Дизайн-референс/систему | Смотри, есть ли skill вроде `anydesign` — вытаскивает палитру/типографику из чужого сайта |
| Обзор рынка (что все качают) | GitHub trending + Reddit жалобы = карта болей |
| Годный ли репозиторий | Дата последнего коммита + звёзды + issues без ответа >6 мес = красный флаг |

## Common Mistakes

- **Берёшь первый результат вместо топ-3 сравнения** — теряешь контекст, что уже пробовали другие
- **Ставишь чужой код без просмотра** — риск для пользователя, всегда показывай, что внутри, прежде чем клонировать
- **Пересказываешь источник вместо дистилляции** — навык должен быть инструментом, не конспектом
- **Не проверяешь дубли** — сначала глянь, нет ли уже похожего скилла в `/mnt/skills/user/`, прежде чем предлагать новый
