# CLAUDE.md

This file gives Claude Code (and other AI coding agents) the context needed to work
in this repository.

## What this repository actually is

**Bipolarochka is not an application codebase.** There is no source code, package
manifest, build system, linter, or test suite in this repo — it is a personal
sandbox for Claude Code / Codex agent configuration: plugin marketplaces, imported
skills, and auto-generated "ECC" (agent-config) bundles. Don't assume TypeScript,
Node, or any other stack is present just because some generated files mention it —
verify with `git ls-files` / `Glob` before trusting claims made in generated docs
(see "A note on the ECC bundle" below).

`README.md` is a single line: "my first but not last" — treat this as an evolving,
early-stage personal repo, not a production project.

### `.claude-plugin`

Declares the `superpowers-dev` marketplace, currently exposing one plugin,
`superpowers` (v5.1.0) — a core skills library (TDD, debugging, collaboration
patterns). This is marketplace *metadata*, not the plugin's own code (the plugin
itself lives upstream, not in this repo).

### `skills-lock.json`

Lockfile for skills pulled in from other repos. Currently pins:
- `motion-design` from `LottieFiles/motion-design-skill` (hash-pinned).

If you add or update an imported skill, update this lockfile's hash entry to match.

### `.agents/skills/motion-design/`

A full imported skill covering motion/animation design (timing, easing,
choreography, Disney animation principles adapted for UI). Framework-agnostic
(CSS, Framer Motion, GSAP, Lottie, Spring). Treat this directory as **vendored —
don't hand-edit it**; update it by re-pulling from the upstream skill repo and
bumping `skills-lock.json`.

### The "Bipolarochka" repo skill (`.claude/skills/Bipolarochka/` and `.agents/skills/Bipolarochka/`)

Both copies are identical, auto-generated by a tool called **ecc-tools** from a
git-history/repo scan (see `.claude/ecc-tools.json`, generated 2026-05-29). It
claims this is a "TypeScript codebase" with kebab-case file names, relative
imports, named exports, and `*.test.*` test files.

**⚠️ This content does not reflect any real code in this repo** — there is no
TypeScript, no `src/`, no tests. It was almost certainly generated from a mostly
empty repo state (few/no commits) and is generic boilerplate, not observed
convention. Do not treat it as authoritative. If real application code is added
to this repo later, this skill file should be regenerated or rewritten to reflect
the *actual* stack and conventions, and this CLAUDE.md should be updated to match.

### `.claude/homunculus/instincts/inherited/Bipolarochka-instincts.yaml`

Also ecc-tools-generated: a list of low-confidence (0.6–0.9) "instincts" (naming
conventions, commit style, test location) inferred from the same sparse repo scan.
Same caveat applies — these are placeholders, not verified conventions.

### `.claude/identity.json` / `.claude/ecc-tools.json`

`identity.json` sets a suggested assistant persona (technical, detailed,
TypeScript domain). `ecc-tools.json` is the full manifest/audit report from the
generation run, including a "reference set readiness" self-score (14/100-ish —
most evidence categories are `"missing"`). Useful only as a record of what
ecc-tools produced and when; not something to hand-maintain.

### `.codex/`

Configuration for the Codex CLI, mirroring the Claude-side setup:
- `AGENTS.md` — Codex's own entry-point doc; supplements this file for Codex.
- `config.toml` — MCP servers enabled by default (GitHub, Context7, Exa, Memory,
  Playwright, Sequential Thinking) plus a multi-agent baseline (`max_threads = 6`,
  `max_depth = 1`).
- `agents/explorer.toml`, `agents/reviewer.toml`, `agents/docs-researcher.toml` —
  read-only sub-agent roles (evidence gathering, correctness/security review, API
  verification respectively), all pinned to `gpt-5.4`.

## Working in this repo

- **There is no build, lint, or test command.** Don't invent one (e.g. don't add
  `npm test` instructions) unless you've actually added a project with real
  tooling — confirm first.
- **Vendored/imported content** (`.agents/skills/motion-design/`,
  anything pinned in `skills-lock.json`) should be updated via re-import, not
  hand-edited in place.
- **ecc-tools-generated files** (anything listed in `.claude/ecc-tools.json`'s
  `managedFiles`) are regenerated by an external tool; if you edit them by hand,
  expect a future ecc-tools run to overwrite your changes unless the tool merges.
- **If you add real application code**, also add real project docs (build/test/lint
  commands, dependency manager, directory layout for source vs. tests) to this
  file, and flag the auto-generated `Bipolarochka` skill/instincts files as stale
  so a future agent doesn't trust their fabricated "TypeScript, kebab-case" claims
  over the real, observed conventions.

## Git conventions actually observed

The real commit history (not the generated "instincts") shows two patterns:
- Short, freeform commit subjects (e.g. `Add LottieFiles motion-design skill`).
- A run of `feat: add Bipolarochka ECC bundle (<path>)` commits, one per
  generated file, from the ecc-tools import.

Prefer clear, conventional messages (`feat:`, `fix:`, `docs:`, etc. or plain
imperative summaries) consistent with the human-authored commits above.
